# 独立项目后的扩展方向

以下是后续建议，本次尚未实现。

| 优先级 | 功能或结构 | 对当前工具的价值 |
| --- | --- | --- |
| 1 | 学习记录 JSON 导入导出 | 在正式换域名前迁移收藏、自测设置、最近查询与阅读位置；备份带版本号，导入时验证结构 |
| 1 | 为课文与注释引入稳定 ID | 收藏不再依赖数组位置，后续增删、排序和教材更新更安全；旧编号需显式迁移 |
| 1 | 按册次／篇目拆分教材数据，并记录教材版次、来源与校对状态 | 增加教材版本、逐篇校订、审核差异更方便；异步加载时应提供加载失败反馈 |
| 2 | PWA 与离线缓存 | 手机添加到主屏幕，在线版访问后离线阅读；需处理缓存版本与更新提示，继续提供离线单文件下载 |
| 2 | 生词本、掌握程度与间隔复习 | 在收藏基础上记录熟悉度、安排复习；先本地实现，无需账号服务 |
| 2 | 逐句译文、朗读音频、背诵遮罩 | 原文、注释、译文和音频分别维护；补充内容需要来源和授权，不能视作已校订教材内容 |
| 3 | 全文搜索索引与 Web Worker | 内容增长后可避免复杂搜索阻塞界面；当前规模先测量再增加复杂度 |
| 3 | 自动检查与页面回归 | 每次改动验证数据引用、课文数量、检索与移动端主要流程，减少维护风险 |
| 按需 | 多端同步、教师共享词单与内容后台 | 需要额外后端、身份验证与权限设计；GitHub Pages 本身仅托管静态文件，浏览器中不能存私密 API 密钥 |

当前拆分保留原生 JavaScript，不急于引入 React 或 Vue。现阶段数据、纯函数、交互和样式分开即可有效维护。等出现大量共享组件或复杂页面状态，再评估框架与构建工具。
